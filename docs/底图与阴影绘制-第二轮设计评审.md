## 其它次要问题（P2 / 备注）

1. **SOLID 填充边界的所有权**（§5.5 注释）：详设注释称"项目 ToolDraw 同款写法，不做手动 delete"，但 ToolDraw::create_hatch 实际**做了手动 delete**（ToolDraw.cpp:633-635，在 appendAcDbEntity **之后** delete edges）——这本身是 ToolDraw 的**潜在 bug**（hatch 通过 appendLoop 已接管 edges，再次 delete 等于双重释放，可能引发崩溃）。详设 §5.5 不做 delete 才是符合 ARX 文档的正确做法，**建议把 §5.5 注释中"ToolDraw 同款"改为"沿用 ARX 文档：所有权交 hatch"**，并对 ToolDraw.cpp:633-635 同步加 P2 任务清单。

2. **`base_map.dwg` 文件存在性检查**（§5.3 行 262）：调用 `CUtils::FileExists(dwgPath)`——**该函数不存在**（Grep 全工程无 `FileExists` 定义/声明，仅 CreateColumnView.cpp:111-112 用 `PathFileExists`，来自 shlwapi.h）。建议改为 `#include <shlwapi.h>` 后 `PathFileExists(dwgPath)`，或 `GetFileAttributes(dwgPath) != INVALID_FILE_ATTRIBUTES`。

3. **`ColorIndex 256**`（ByLayer）在拟建轮廓：§5.4 调用 `AddDbPolyline(pts, kProposedWidth, true, NULL, 256)`——256 是 ByLayer，"底图-拟建建筑物"层颜色须显式配置为"白/黑"（§3.2 表规定色 7）；详设未明示该层 EnsureLayer 时是否设色。需在 §3.2 / §5.4 加一句"EnsureLayer 创建该层后 setColor(7)"。

4. **`PrepareOutline` 严格度**：§5.6 `ParseOutline` 在任一顶点类型不匹配时 `return false`——单点错即整栋建筑失败。建议改 `continue` 跳过非法点 + 累计到 ≥3 再返回 true（更稳健）。

5. **`CUtils::EraseBlock` 在底图层实体先于块定义删除**：当存在"块参照 + 其它实体混在'底图-现状'层"时，§5.2 先 EraseLayerEntities 会把块参照 + 其它同层实体一起删，再 EraseBlock 删块定义。**没问题**，但若用户曾在"底图-现状"层手画了辅助线（非块参照），重复执行会**默默删除用户内容**——这是设计语义（"底图-*"层归插件管辖），应在 §8 异常表加一条说明。

6. **`_call_cad` 默认 120s 超时**：draw_gateway.py 行 168 `def _call_cad(path, timeout=120)`，底层 `requests.post(...timeout=120)`——底图导入场景下 `create_plan_view` 一次性读 DWG + 提取拟建 + 配准 + 建块，可能超 120s（10MB 底图 × 多次解析），建议专门给 `plan` 视图 timeout 提到 300s。
