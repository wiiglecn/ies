# 平面图剖线与编号一致性 —— 实施方案 V1（已实施 · 2026-10-21）

> 状态：**已实施**，VS2005 编译 0 错误，CAD 端到端待复测。
> 链路前提：**不经过网关 `draw_gateway.py`，调用方直接请求 ARX 的 7100 接口**。
> 接口侧摘录见 `docs/CAD勘察出图插件-接口文档.md` §13。

**实施偏差说明（相对本文原案）**：`plan_base` 在 ARX 侧无读取方（`grep plan_base` 在 src/features 下零命中），故未落盘其项目级文件，避免造一个没人读的文件；其余按方案落地。

---

## 1. 目标

1. 平面图上绘制**剖切位置线（剖线）**，按理正标准出符号。
2. **平面图 / 剖面图 / 图例三处钻孔编号一一对应**，不允许对不上。
3. 平面图中的孔必须使用**图例里那套孔图**（同一份类型→图块映射）。
4. 剖面图编号**从接口读取**，不再由页数自增。
5. **按项目隔离数据文件**，彻底关闭不同项目数据混用的口子。

---

## 2. 现状与问题定位

### 2.1 数据文件的写入方是 ARX（非网关）

`src/AiApiRequest.cpp:293-328` 收到请求后即刻落盘：

```cpp
// 同一份数据写三处副本
fopen("D:/project/ies/cad/exploration/Debug/钻探编录表.json", "w");
fopen("D:/project/ies/cad/exploration/project/钻探编录表.json", "w");
fopen("D:/project/ies/cad/exploration/Release/钻探编录表.json", "w");
// section_params 同理写 Debug/ + project/
```

现有缺陷：

| # | 问题 | 后果 |
|---|---|---|
| 1 | 路径写死 `D:/project/ies/...` | 换目录即失效；已有 `CUtils::GetArxFolder()` 未使用 |
| 2 | 三份副本 | 只有 `project/` 那份被读（`CreateBaseView.cpp:251`），其余是死数据 |
| 3 | 文件名不含项目标识 | **串项目的根源** |
| 4 | 中文路径裸 `fopen` | 依赖系统 ANSI 代码页 |
| 5 | 网关 `draw_gateway.py:53-55` 也写同名文件（双写） | 目标链路去掉网关后即消失 |

读取方：

| 文件 | 读取位置 |
|---|---|
| 钻孔数据 | `features/CreateBaseView.cpp:251`（平面图 / 柱状图 / 剖面图共用） |
| 剖面参数 | `features/CreateSectionView.cpp:264` |
| 底图配置 | 网关侧 `draw_gateway.py:984-995`（若保留网关才涉及） |

### 2.2 编号三处口径不一

- 剖面图：取 `boreholeData` 的 JSON key（对象形态）；
- 平面图孔位标注：取 JSON key（`CreatePlanView.cpp` 中 `arrayName`）；
- 平面图图例：取孔节点字段（与 arrUsedHoles 收集方式不同）。

实测当前数据 37 孔 key 与 `钻孔编号` 字段完全一致，尚未暴露问题，但机制上随时可错位。

> **2026-10-22 定稿**：`boreholeData` 改为**钻孔对象数组**（不再有 JSON key），主键统一收敛到 `钻孔编号` 字段——见 §5 / §9。

### 2.3 平面图孔符号与图例不一致（根因）

- 数据 `钻孔类型 = "技术孔"`，而 `support/block_define.json` 的 32 个符号名均为国标叫法，**无「技术孔」**；
- `FindBlockNameByHoleName()` 匹配失败 → 静默回落默认 `GKJBK`（鉴别孔）；
- 且平面图（`CreatePlanView.cpp:148`）与图例（`:534`、`:611`）**各调一次**该函数，逻辑重复。

> **已调整（实施时用户给出理正符号口径）**：`ResolveHoleBlock` 增加**理正习惯叫法别名表**作为国标表未命中时的兜底——
> 技术孔/控制钻孔 → `GKkzzk`；一般钻孔/鉴别孔 → `GKybzk`；工程观测孔 → `GKgck`；普通钻孔 → `GKzk`。
> 因此「技术孔」不再是静默回落，而是明确命中 `GKkzzk`（控制钻孔）。

### 2.4 无剖线

`CreatePlanView.cpp:652` 已有「地质剖面线及编号」图例占位段，实体绘制尚未实现。

### 2.5 剖面图编号自增

`drawHeader()` 现按 `总页数------当前页码′` 生成，未读接口标题。

## 3. 目标数据流（直连 7100）

```
调用方 ──POST body(boreholeData + sectionParams[+planBase])──▶ ARX 7100
                                    │
                                    ├─ ① 解析项目名 → 净化
                                    ├─ ② 落盘 project/{项目名}-钻探编录表.json
                                    │        project/{项目名}-剖面图参数.json
                                    │        project/{项目名}-plan_base.json（若传）
                                    ├─ ③ 校验（编号 / 项目名 / 孔类型）
                                    └─ ④ 主线程出图；各 view 读本次项目同名文件
```

要点：**每次请求自带全量数据**，落盘文件名由项目名决定，读取前校验项目名一致性。

---

## 4. 项目隔离规则

### 4.1 项目名来源

优先级：

1. body 顶层 `projectName` / `工程名称`（旧 `project_name` 仍可读，打 WARN）；
2. 孔节点 `工程名称` 字段 —— **要求全部孔取值一致**，不一致直接报错拒绝出图（不猜、不取第一个）。

### 4.2 命名

```
project/{项目名}-钻探编录表.json
project/{项目名}-剖面图参数.json
project/{项目名}-plan_base.json
```

`{项目名}` 净化规则（公共函数，ARX 内唯一实现）：

- 去除 `\ / : * ? " < > |` 及首尾空白与控制字符；
- 长度截断（建议 40 汉字 / 80 字符）；
- 净化后为空 → 报错拒绝。

### 4.3 读取侧校验（关键）

- 读取时校验文件内记录的项目标识与本次请求项目名一致；
- 不一致 → **报错中止**，不静默使用；
- 文件不存在 → 报错，明确提示"请先传入对应业务数据"。

### 4.4 清理

删除 `project/` 下三个旧固定名文件（`钻探编录表.json`、`剖面图参数.json`、`plan_base.json`），使"找不到就报错"，不留回退路径。

### 4.5 不项目化的共享配置

`support/block_define.json`、`support/pat_define.json`、`support/cad.lin`、`support/block/*.dwg`。全项目共用一套，变更即全局升级。

## 5. 编号口径统一

- **查询主键**：孔节点 `钻孔编号` 字段（数组形态下不再有 JSON key；唯一、必填）。
- **显示编号 / 块名**：同一 `钻孔编号` 字段；缺失时打 WARN 并退化成 `KsHole_<序号>`。
- **重名检测**：数组中出现相同 `钻孔编号` → 报错。
- 平面图孔位标注、平面图图例、剖面图三者**同源**，均走同一解析函数。

---

## 6. 孔符号一致性

新增公共解析（供平面图与图例共用）：

```
KsResolveHoleBlock(钻孔类型) → 图块DWG路径
  命中 block_define.json → 使用其「图块名称」
  未命中                 → WARN + 约定兜底符号（默认 GKJBK）
```

- 同一进程内**只此一处**解析，从机制上排除平面图与图例不一致；
- 告警落 `[CAD WARN]` + 响应 `warnings`（贯穿未完成命中%），而非静默替换。

---

## 7. 剖切位置线（平面图）

输入：`sectionParams` 的剖面组，每组含标题与有序孔号列表。
绘制规则（理正标准）：

1. 按孔序取各孔平面坐标，**复用同一套 XY 映射**（含现有 bSwapXY 自动判定）；
2. 顺序连线（多段线），新建独立图层便于开关；
3. 两端剖切符号：短剖切粗线 + 剖视方向指示 + 剖面编号文字（编号取该组标题，与剖面图完全一致）；
4. 图例区复用现有「地质剖面线及编号」占位段，补连线示意与编号说明。

异常策略：

- 某组孔号不在本次 `boreholeData` 中 → 跳过该剖线，WARN 列出缺失孔号；
- `sectionParams` 未提供 → **不画剖线并告警**（平面图其余部分照常）。

---

## 8. 剖面图编号

- 主编号取该剖面组的 `标题`（如 `A-A`）；
- 多页时补**组内页码**后缀 `-1` / `-2`；多页分组时页码在组内重新计数；
- 保留原「总页数------当前页码′」作为副标注（按既定选择，两者并存）；
- 接口未提供标题 → 退回页数自增并打 WARN。

---

## 9. 7100 请求体契约

> **2026-10-21 修订**：请求体顶层字段统一改为**小驼峰命名**（对齐 `§13.0 命名约定`）。下表已更新；下划线拼写仅作过渡期兼容，命中时打 `[7100] WARN`。

| 字段（驼峰 · 现行） | 废弃拼写 | 必填 | 说明 |
|---|---|---|---|
| `boreholeData` | `borehole_data` | 是 | **钻孔对象数组**；`钻孔编号` 为孔唯一标识且必填；每孔须含 钻孔编号 / X坐标(m) / Y坐标(m) / 孔口高程(m) / 地层列表；建议含 钻孔类型、工程名称。（旧的 `{孔号: 对象}` 形态仍兼容，打 WARN） |
| `sectionParams` | `section_params` | **平面图 / 剖面图必填** | 剖面组数组：标题 + 有序孔号 + 标高参数 |
| `projectName` / `工程名称` | `project_name` / `工程名称` | 否 | 缺省则取孔内 `工程名称`，要求全孔一致 |
| `planBase` | `plan_base` | 否 | 底图配置，参与项目化命名 |

## 10. 校验与告警清单

| 级别 | 场景 |
|---|---|
| 报错中止 | 项目名缺失或空；孔间 `工程名称` 不一致；业务编号重名；项目文件不存在或项目名不匹配 |
| WARN | `钻孔编号` 缺失（退化成 `KsHole_<序号>`）；`钻孔类型` 未在 block_define 命中（用兜底符号）；剖线所需孔号缺失；接口未提供剖面标题 |
