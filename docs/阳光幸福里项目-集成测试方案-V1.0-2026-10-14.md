## 1. 测试目标

1. **真实数据回归**：以"环江阳光幸福里"项目 37 个钻孔（ZK1~ZK37）+ 真实底图（`05阳光幸福里 总平面规划图10.4.dwg`，5.4 MB）为输入，验证柱状图、平面图（流程一/流程二）、剖面图三类出图能力在生产环境下的端到端正确性。
3. **P0 修复全面覆盖**：对 2026-10-14 P0 修复（详见 `评审-P0 改造蓝图-2026-10-14.md`）落地的 8 个关键项逐项实测——D1（JSON body 含底图键 → 400）、SSRF（回环拦截）、告警必达（绝不返 5xx）、BASEPOINT 甲方案（`ptInsert' = ptInsert + s·R(θ)·B`）、平面图增强（A1~A6 标识符 + 9 个新方法）、图例去"及层数"、ParseRegistration + ComputeRegistration 最小二乘接口并存、形态 B 三接口 + 旧 `/api/draw` 四接口并存——逐项验收。
3. **双形态架构互验**：对**形态 A**（AutoCAD 2007 + ARX 内嵌 :7100 单接口 `POST /api/draw`）与**形态 B**（Flask 网关 :7200 + ARX :7100 三接口 `POST /api/draw/{column,section,plan}` + 旧 `/api/draw`）同时验证，确认两种形态在 P0 修复后行为一致且接口契约符合接口文档 V1.1。
4. **与理正勘察对比**：以理正 8.0 / 9.0 平面图（`阳光幸福里-理正（8.0）-2026-06-26 20_24_04.txt`、`阳光幸福里-理正（9.0）-2026-06-26 20_23_41.txt`）为参照基准，对比钻孔点位、底图对齐、出图比例三项关键参数，验证与理正结果的偏差在工程可接受范围。

**【形态】** A（ARX 内嵌 :7100 单接口）

**【前置】**

- ☑ `SLINIT` 已执行，看到 `[CAD DEBUG] Listening started`

- ☑ 业务系统已将该 JSON 转换为接口文档 §9.1 定义的 borehole_data 层级对象结构

**【测试数据】**
- `borehole_data`：从 `cad_client/阳光幸福里-钻探编录表.json` 抽取 ZK1~ZK37 全部 37 孔（每孔含 hole_no / x / y / elevation / depth / hole_type / layers[]）

**【HTTP 请求】**
```bash
curl -X POST http://localhost:7100/api/draw \
  -H "Content-Type: application/json; charset=utf-8" \

```

**【预期响应】**
```json

  "status": "success",
  "results": { "column": { "status": "success" } },
  "errors": {}
```

HTTP 200。

**【验收点】**
- ☐ HTTP 200 + `status=success`

- ☐ 总耗时 < 60s（参考形态 A 实测 352 孔 25.3s，37 孔应在 30s 内）

#### 用例 C01-B

**【形态】** B（Flask 网关 :7200 三接口 `/api/draw/column`）

**【目的】** 验证形态 B 网关 `/api/draw/column` 对 37 孔数据走完整链路——网关 `_resolve_form_json("borehole_data")` 解析、英文→中文键翻译、落盘、调用 ARX `/ai/feature/create_column_view`、`auto_zoom=true` 默认行为。

**【前置】**

- ☑ borehole_data JSON（37 孔层级结构）已准备

**【测试数据】**
- `borehole_data`：同上 C01-A
- `auto_zoom=true`（默认）

**【HTTP 请求】**
```bash
curl -X POST http://localhost:7200/api/draw/column \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{
    "borehole_data": { /* 37 孔层级对象，结构同 C01-A */ },
```

```bash
curl -X POST http://localhost:7200/api/draw/plan \
```

```json
  "degraded_to": "process1_no_basemap"
}
```
HTTP **200**（**绝不返 5xx**——PM 决策 9 加粗约束）。

**【验收点】**
- ☐ HTTP **200**（告警必达，不返 5xx）
- ☐ `warnings[0]` = `底图未被采用：base_map_url 校验未通过（详见网关日志）`（**不写明拒因，避免给攻击者反馈**——接口文档 V1.1 §7.10 攻击行为告警口径）
- ☐ `degraded_to="process1_no_basemap"`（按流程一继续出图）
- ☐ `_is_loopback("127.0.0.1")` 返回 `True`（IPv4 回环命中）
- ☐ 网关 stdout/stderr 日志（stdout）打印 `ssrf denied host: 127.0.0.1`（仅运维可见，不暴露给调用方）
- ☐ ARX 端继续出图（37 孔布孔 + 图例）
- ☐ **CAD 端必须显式告知用户**（`acedAlert` 或 `acutPrintf`）——详设 V1.7 §9.3 告警必达口径

**【错误注入】**
- `http://127.0.0.1:80` → 同上
- `http://[::1]:80/x.dwg` → 同上（IPv6 回环）
- `http://localhost/x.dwg` → DNS 解析到 127.0.0.1，仍命中
- `http://10.0.0.5/x.dwg`（私网）→ 默认放行；若启动时带 `--ssrf-whitelist-cidr 192.168.0.0/16` 则拒绝
