## 0. 三十秒速读

- 这是一个 **AutoCAD 插件**，不是 Web 服务。外部系统（网页/App/Python 脚本）把钻探编录数据以 JSON `POST` 到 CAD 本机的 `http://localhost:7100/ai/feature/create_xxx`，插件就在当前图纸里把**平面布置图 / 剖面图 / 柱状图**画出来。
- 代码只有一处需要维护：`cad/exploration`（C++ / MFC / ObjectARX，VS2005 编译，**Unicode** 工程）。
- 数据落盘是**按项目隔离**的：`<ARX目录>/project/{项目名}-钻探编录表.json` 与 `{项目名}-剖面图参数.json`。
- 接口权威口径是 `docs/接口文档1.1.md`（当前 **V1.2**，2026-10-22）。顶层字段是**小驼峰** `projectName / boreholeData / sectionParams`，`boreholeData` 是**钻孔对象数组**，主键是 `钻孔编号` 字段。
- 最容易踩的坑集中在两处：**ARX 文档写锁**与**源码编码（GBK/UTF-8）**。见 §7。

## 1. 项目在做什么

坤盛智能勘探（IES）的 CAD 出图环节。输入是勘察钻探编录表（Excel → JSON，由 `cad_client/excel_to_json.py` 一类脚本转换），输出是勘察三图：

| 图 | 入口类 | 说明 |
| --- | --- | --- |
| 勘探点平面布置图 | `features/CreatePlanView.cpp` | 在当前图纸（用户已打开的**带底图** DWG）上叠加钻孔符号、孔口高程/孔深标注、图例、剖切位置线 |
| 工程地质剖面图 | `features/CreateSectionView.cpp` | 标尺、地面线、水位线、钻孔柱、地层分界线（跨孔按地层名称关联）、填充花纹、层名序号、时代成因代号、取样/风化符号、表头、分页 |
| 钻孔柱状图 | `features/CreateColumnView.cpp` | 以模板 DWG 块为底，替换孔号/标高/孔深/日期/制图人，填充分层，画孔深表 |

## 3. 运行链路（一次请求发生了什么）

```
外部系统
   │  POST http://localhost:7100/ai/feature/create_section_view
   ▼
AiApiServer (mongoose, 监听 0.0.0.0:7100)
   ▼
AiApiRequest::handle
   ├─ 路由表命中：/ai/feature/create_section_view → "create_section_view" → WM_USER_FEATURE_SECTIONVIEW
   ├─ 解析 body（cJSON）
   ├─ 解析项目名：body.projectName 优先，否则孔内「工程名称」（要求全孔一致，否则报错）
   ├─ 落盘：<ARX>/project/{项目名}-钻探编录表.json、{项目名}-剖面图参数.json
   └─ 追加日志：<ARX>/7100_request.log（一行一条原始请求 JSON）
   ▼  PostMessage(主线程)
ApiMessageWnd::WindowProc  →  case WM_USER_FEATURE_SECTIONVIEW → new CCreateSectionView().Execute()
   ▼
Execute():
   prepare()            读 project/{项目名}-钻探编录表.json，校验 projectName / boreholeData
   startTrans()         开 ARX 事务（≠ 文档锁）
   actionBefore()       ★ 取文档写锁 + 打开模型空间为写
   EnsureLayer / 绘图    ★ 所有写库操作必须在 actionBefore 之后
   actionEnd()          提交事务 + 解锁
```

关键点：**HTTP 线程不碰数据库对象**，一律 `PostMessage` 到主线程窗口过程里画；`ApiMessageWnd` 是线程与 CAD 的唯一桥。

本地不带 HTTP 也能出图（调试常用）：CAD 命令行执行 `SLINIT` 启动服务；`SLPLANVIEW / SLSECTIONVIEW / SLCOLUMNVIEW` 直接调 `Execute()`，走磁盘上已有的项目 JSON。

### 5.3 口径约定（改动前务必对齐）

| 约定 | 说明 |
| --- | --- |
| 顶层字段 | 小驼峰 `projectName / boreholeData / sectionParams`；旧下划线名仍可读但打 `[7100] WARN` |

## 6. 代码结构要点

### 6.1 三个视图类的统一骨架

```cpp
void CCreateSectionView::Execute()
{
    if (!prepare()) return;            // 读项目级 JSON、校验项目名与数据
    ...
    if (this->startTrans()) return;    // 事务
    int ret = this->actionBefore();    // ★ 文档写锁在这里拿到
    if (ret != 0) { aboutTrans(); return; }
    ... EnsureLayer / 画 ...
    this->actionEnd();                 // 提交 + 解锁
}
```

`CCreatePlanView` / `CCreateSectionView` / `CCreateColumnView` 都继承 `CCreateBaseView`（→ `ToolDrawBase`），差异只在 `Execute()` 里画什么。

### 6.2 写库铁律（`tools/ToolDrawBase.cpp`）

```cpp
int ToolDrawBase::actionBefore()
{
    pDoc = acDocManager->curDocument();
    es = acDocManager->lockDocument(pDoc);   // ★ 全项目唯一的文档写锁
    pDb = acdbHostApplicationServices()->workingDatabase();
    pDb->getBlockTable(...); pBlockTable->getAt(ACDB_MODEL_SPACE, pModelSpace, AcDb::kForWrite);
}
```

`startTrans()` **不加文档锁**。建层 `getLayerTable(kForWrite)`、写线型表、`appendAcDbEntity`、改对象——只要排在 `actionBefore()` 之前，就返回 `320 = eWasOpenForRead`（误导性错误码，真实原因是缺写锁）。历史上排查了整整一天，见 `剖面图320错误交接文档.md`。

### 6.3 三图的图层清单

| 图 | 图层 |
| --- | --- |
| 平面图 | `勘察点方案`（孔位）、`勘察剖切线`（剖切位置线，ACI 7 白色，线宽 0.15/短剖切线 0.21）、`勘察点图例` |
| 剖面图 | `地质-地面线`、`地质-地层线`、`地质-水位线`、`地质-地层符号`、`地质-填充花纹`、`地质-钻孔`、`地质-图框`、`地质-图例`、`地质-标贯`、`地质-静探`、`地质-标注栏`、`地质-文字`、`地质-地层编号`、`地质-原位曲线`（14 个）＋ `地质-符号`（按需）＋ `基础底设计标高线` |
| 柱状图 | 不自建图层：直接插入模板块 `support/2007/钻孔柱状图.dwg`，图层随模板块带入；文字样式用 `成果图表体` |

绘制时会临时把目标层设为当前层，**画完必须恢复原 `clayer()`**——曾因不恢复导致图例被误删、剖线画不全。

### 6.4 `CUtils` 里最常用的几个函数

| 函数 | 用途 |
| --- | --- |
| `FindHoleNodeUtf8(cJSON* root, const char* 孔号)` | **按孔号取孔节点**（先按对象键直查旧形态，再遍历数组比 `钻孔编号`）。剖面图里 10 处取孔全靠它 |
| `GetHoleKey(node, idx)` | 取主键（块名/显示名来源）：`钻孔编号` → 对象键名 → `KsHole_<序号>` |
| `ResolveHoleBlock(cfg, 钻孔类型, ...)` | 孔符号块名解析：`block_define.json` 国标 32 条 → 理正别名表（技术孔→`GKkzzk`、一般钻孔→`GKybzk`、工程观测孔→`GKgck`、普通钻孔→`GKzk`）→ 兜底 `GKJBK` + WARN。平面图与图例必须共用此函数 |
| `GetProjectFilePath(title)` / `WriteUtf8File` | 项目级数据文件路径与落盘 |
| `utf8ToTChar` / `TCharToUtf8` | cJSON 的 `char*` 与 `CString` 互转（工程是 Unicode，**不能**直接 `CString(char*)`） |
| `EnsureLayer` / `EnsureTextStyle` / `AddDbText` / `GetEntExtent` | 绘图原语 |

> 禁止再用 `cJSON_GetObjectItem(s_pJsonData, 孔号)` 取孔——数组形态下必落空；也禁止用 `item->string` 当孔号——数组元素里是 `NULL`。

## 7. 八条硬约束（违反必出错，已反复踩过）

1. **写库顺序**：`startTrans` → `actionBefore` → 建层/加载线型/append 实体 → `actionEnd`。加载 `cad.lin` 也算写库，同样要在锁之后，否则**静默失败**，实体 `setLinetype` 找不到线型 → 回落 ByLayer。
2. **GBK 源码**：`features/*.cpp`、`src/Utils.cpp` 等绝大多数是 **GBK + CRLF**。改它们必须用 Python 按 `open(p,'rb').read().decode('gbk')` → 字符串替换 → `.encode('gbk')` 写回；用通用编辑器写中文注释极易落成非 GBK 字节，编译报 `C4819` + 一串 `C2001: newline in constant`。
3. **`AiApiRequest.cpp` 是 UTF-8 BOM + LF**（文件头那句 `// coding: gb18030` 是**过期注释，别信**）。改这个文件用 UTF-8、LF。
4. **跨孔一律按「地层名称」关联**，不能按 `地层编号`——编号是分孔流水号，ZK4 的 `3-2-0` 是强风化泥岩、ZK5 的同号是泥灰岩。另：**孔底不能作为分界线落点**（连到孔底就是错图），对方层为末层时走尖灭。
5. **平面图 X/Y 映射不写死**：`CreatePlanView::Execute` 预扫描全部孔坐标，比较「直接对应」与「X/Y 互换」两种映射下数据包围盒中心与底图包围盒中心的偏移，取小的；底图不可用则默认互换。日志会打印选了哪种。历史上两种数据源 X/Y 顺序曾相反，写死必错。
6. **孔符号解析必须走 `CUtils::ResolveHoleBlock`**，平面图与图例共用一份，禁止各自调 `FindBlockNameByHoleName`。
7. **当前图层保护**：临时改 `clayer` 前保存、画完恢复。
8. **`autPrintf` 必须写成 `CUtils::acutPrintf`**；静态成员（如 `CUtils::s_projectName`）必须在 `.cpp` 里有定义，否则 LNK2001。

## 8. 已实现 / 未实现

### 8.1 已实现（可用）

- 三图出图全流程；项目级数据隔离（换项目不串数据）；请求日志。
- 剖面图：标尺自动取整（数据最低-1 ~ 最高+1）、逐格取整齐米数、跨孔地层按名称连线+尖灭、层合并、层名序号、时代成因代号（专用文字样式 `KS_ERA`，Times New Roman 正体，支持「统+阶」如 `C1Y`）、取样/风化符号同级最小间距 3.2 级联避让、表头编号取 `sectionParams.剖面组[].标题`、多页补 `-1/-2` 并保留 `总页数------页码′`、基础底设计标高线。
- 平面图：孔符号按类型解析、孔号/孔口高程/终孔深度标注、图例（孔符号 + 「地质剖面线及编号」按实际编号逐条）、剖切位置线（编号与剖面图表头**同源**）、坐标自动判定、生成后缩放到底图∪钻孔范围。
- 柱状图：模板块文本替换、分层填充、孔深表、制图人/校对人。

## 9. 故障排查速查

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 连接被拒绝 | CAD 没起 / ARX 没加载 / 没 `SLINIT` | 重新 `arxload` + `SLINIT`，看命令行是否打印 `StartHttpServer` |
| 大量 `320 eWasOpenForRead`，图层全建不出来 | 写库代码排在 `actionBefore()` 之前 | 挪到锁之后（对照 `ToolLayer::create_layer()`） |
| HTTP 200 但图上没东西 | 缺 `projectName` / `boreholeData`，或孔缺 `钻孔编号` | 看命令行 WARN，检查请求体 |
| 线型警告 / 实体线型变 ByLayer | `cad.lin` 加载失败（常见于加载时机不对） | 加载挪到 `actionBefore` 之后 |
| 平面图孔位镜像 / 图例跑到 X≈1963 万 | X/Y 映射判错（模型空间同时存在 274 万与 3652 万量级） | 看日志「坐标自动判定: …」，检查底图范围是否读到 |
| 剖面图跨孔连线乱连 | 按 `地层编号` 关联了（跨孔不可比） | 改按 `地层名称`，末层走尖灭 |
| 编译报 `C4819` / `C2001: newline in constant` | 源文件被写成了非 GBK 字节 | `git checkout -- <file>` 回滚，用 Python 按 GBK 重做 |
| `LNK1168` | CAD 开着，arx 被占用 | 关 CAD，等 3~4 秒再编 |
| 编译"成功"但产物没变 | 在 Git Bash 里调的 `devenv.com` | 换 PowerShell，并核对 `.arx` 时间戳 |
| 填充缺失 | `pat_define.json` 没配该岩性 | 补映射（会打 `[CAD WARN] 未找到岩性 …`） |
| 图例/剖线莫名消失 | 绘制时改了当前层没恢复 | 保存/恢复 `clayer()` |

## 10. 调试手法（省时间的几个）

1. **从请求原文复算**：`Debug/7100_request.log` 一行一条原始 JSON，取最后一条 `json.loads` 即得真实入参；复杂逻辑（剖面连线）在 Python 里复算比在 CAD 里反复出图快一个数量级。
2. **看命令行输出**：`CUtils::acutPrintf` 全打在 CAD 命令行，三图都有 `[平面图] / [7100] / [CAD WARN]` 前缀日志（坐标判定、孔插入点、剖线绘制条数、缺孔跳过等）。
3. **本地离线出图**：`SLPLANVIEW` / `SLSECTIONVIEW` / `SLCOLUMNVIEW` 直接读磁盘项目 JSON 出图，不用起 HTTP 客户端。
4. **改完 GBK 文件自检**：写回后 `decode('gbk')` 再解一遍，并 `grep` 关键行确认替换真的落盘了（个别编辑器"假成功"）。
