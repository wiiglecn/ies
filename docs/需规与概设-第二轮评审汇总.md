## TL;DR

本轮评审的价值不在"改架构"，而在**发现 3 个会让实施"编不过 / 画错 / 接口收不到参数"的硬伤**，并修正了两位成员各自的 2 处误判。P0 必须改，其余按 P1→P2 排序。

## 一、P0（必修：不改会直接失败）

### P0-1｜详设接口"声明 / 实现 / 调用"三处不一致 → 编译或链接失败
- 详设 §4 头文件：`bool ImportBaseMap(const cJSON* cfg);`（1 参）
- 详设 §5.3 实现：`bool ImportBaseMap(const cJSON* cfg, const ShadowParam& sp);`（2 参）
- 详设 §5.1 调用：`ImportBaseMap(bm, sp);`（传 sp）→ **编译不过**
- `DimBaseMapReference()` 在 §5.3 有实现、有调用，但 §4 头文件**没有声明** → **链接错误**
- **改法**：§4 头文件声明块补两行：
  ```cpp
  bool ImportBaseMap(const cJSON* cfg, const ShadowParam& sp);
  void DimBaseMapReference();
  ```

### P0-2｜网关 multipart 提交时，`plan_base` / `section_params` 永远读不到
- 详设 §9.3 三个接口同时用 `body = request.get_json(force=True, silent=True) or {}`，又用 `request.files` / `request.form` 取底图。
- 当客户端按文档示例以 **multipart/form-data** 上传底图 DWG 时，`get_json` 解析失败 → `body = {}`。代码里 **只有 `borehole_data` 有 `request.form` 兜底**，`plan_base`、`section_params` 没有 → **这两个配置永远不会落盘**，`DrawBaseMap()` 与剖面参数彻底失效。
- 佐证：现有网关 `cad_server/draw_gateway.py:186` 同样只用 `get_json(force=True, silent=True)`，本就只支持 JSON、不支持 multipart。
- **改法**：三接口统一从 `request.form` 取字段（`borehole_data` / `section_params` / `plan_base` 均为 form 字段），再 `json.loads` 解析；删除 `request.get_json(force=True)`。

### P0-3｜"平移轮廓 + SOLID 填充"会把建筑本体填灰（且"双 loop"修法几何不成立）
- 现象：拟建建筑**只画轮廓、不填充内部**，而 SOLID 填充的是**整个平移后的轮廓面 S**。S 与原轮廓 P 在建筑内部大面积重合 → 建筑内部被填充成灰色，**不是"右下角的影子"**。
- **纠偏**：架构师提出的"外环=P、内环=S"双 loop 方案**几何不成立**——P 与 S 互不包含（S 在右/下越出 P，P 在左/上越出 S），内环会穿出外环，hatch 会评估失败或填充错乱。
- **正确改法（二选一）**：
  - **① 首选（最稳）**：影子 = **平移后轮廓的细线**（`AddDbPolyline(s, 0.18, true, NULL, 253)`，色 253、不填充）。几何永远正确，"影子线"也是勘察/总图通行画法。
  - **② 若要面填充**：对 `S − P` 做布尔差（`AcDbRegion::booleanOper(kBoolSubtract)`），对所得区域填充或绘轮廓。
- 依据：详设 §5.5、§6.2。

## 二、P1（高风险：会造成返工或线上问题）

| # | 问题 | 说明与改法 |
| --- | --- | --- |
| P1-1 | **底图 DWG 版本兼容未约定** | AutoCAD 2005 只能读 ≤2004 格式(DWG)，2007 只能读 ≤2007。甲方给 2010+/2018 总图时 `readDwgFile` 直接失败 → 底图全降级。需规 §5.2 应**硬性要求"甲方另存为 AutoCAD 2004 格式"**；§6 补"高版本 DWG 应提示并降级、不崩溃"验收。 |
| P1-2 | **"无状态"表述与"固定路径落盘覆盖"矛盾** | 每次调用覆盖写同一 `project/*.json`、`support/底图/`，并非真无状态；多用户/多项目并发会互相覆盖（`_lock` 只串行、不隔离）。需规 §2/§6 的"系统不保存项目信息 / 不残留上次数据"应改为"不建项目档案；复用同一工作目录并覆盖上一份数据；多项目须独立部署"。 |
| P1-3 | **SSRF** | `base_map_url` 只校验 http/https 与 `.dwg`，未拦内网/回环/链路本地（127.x、10.x、172.16-31.x、192.168.x、169.254）。下载前用 `ipaddress` 解析并拒绝私有网段。 |
| P1-4 | **下载与出图全在 `_lock` 内串行** | 单次最坏 30s(下载) + 120s(CAD) + 30s(zoom) ≈ 180s 阻塞**所有**并发调用。把 `_save_base_map` 移出锁；`plan` 视图的 `_call_cad` 超时单独提到 300s（大底图）。 |
| P1-5 | **底图目录只增不删** | `support/底图/` 按文件名落盘、永不清除，不同项目累积（50MB × N）。改 `sha256(data)[:16]` 命名 + 同名复用 + 定期清理 N 天未访问文件。 |
| P1-6 | **配准矩阵正确性：不要手搓矩阵** | 详设 §5.8 `BuildRegMatrix` 返回 `mT*mR*mS`，注释自述"列向量语义"。AcGe 乘序是经典坑，两种约定结果相反（见"分歧"）。**更稳做法**：不手搓矩阵，直接用已插入块参照的 `AcDbBlockReference::blockTransform()` 取"源DWG坐标→当前图 WCS"的真实变换，一次绕开乘序之争 **且** 自动包含块 BASEPOINT 与任何自动缩放。项目内 `src/PolylineMarker.cpp:176` 已有先例。 |
| P1-7 | **大底图被读两次** | `ExtractProposedFromBaseMap` 自建 `AcDbDatabase` 与基类 `GetExtDb` 职责重复。改为 `GetExtDb(dwgPath)` 复用缓存（`CreateBaseView.cpp:35-58` 已实现路径级缓存）。 |
| P1-8 | **`CUtils::FileExists` 不存在** | 详设 §5.3 仍调用之。全局搜索无此函数；改用 `PathFileExists`（`CreateBaseView.cpp:3` 已 `#include <shlwapi.h>`；`CreateColumnView.cpp:111` 已在用）。 |
| P1-9 | **"不访问外网"与 URL 下载自相矛盾** | 需求文档 NFR-8 / 需规 N3 称"不访问网络"，但 FR-7.4 允许 `base_map_url` 下载。统一为"仅网关为获取底图发起下载，插件全程不联网"。 |
