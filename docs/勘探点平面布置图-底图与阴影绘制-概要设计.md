### 0.3 柱状图现状设计（反推，`CCreateColumnView`）

**成图模式：模板块 + 占位符替换**（非逐元素几何绘制表头）：

1. **逐孔布局**：遍历 `s_pJsonData` 顶层（每孔一个模板块实例）；孔间距 `space=222.6865`，逐孔 `ptInsert.x += space` 右移；每 10 孔泵消息防卡死；
2. **模板导入**：`ImportDwgAsBlock(support/{CADYEAR}/钻孔柱状图.dwg, ptInsert, arrayName)`，块名 = 钻孔编号；
3. **占位符替换** `CollectTexts`：遍历块定义内单行文本，识别 `[xxx]` 占位符，经 `s_fieldMap`（15 项）映射表取值替换：

| 占位符 | 数据源 | 占位符 | 数据源 |
| --- | --- | --- | --- |
| [page_no] / [page_count] | 当前页 / 总页码 | [coordinate_x] / [coordinate_y] | X/Y坐标（加 `x=`/`y=` 前缀） |
| [project_name] / [project_no] | 工程名称 / （预留） | [start_date] / [completion_date] | 开孔 / 终孔日期 |
| [hole_no] | 钻孔编号 | [water_depth] | 稳定水位(m) |
| [elevation] | 孔口高程(m) | [survey_unit] | 公司名称 |
| [diameter] | `JsonConfig.profile.HOLE_DIAMETER_ZK` | [mapping] / [check] | 制图人 / 校对人（块，见下） |

4. **[mapping]/[check] 特殊处理** `CollectMapping`：在占位符位置插入 `support/{CADYEAR}/制图人.dwg / 校对人.dwg` 块参照，并按包围盒**非等比缩放到 23×8**（`sx=23/w, sy=8/h`），对齐占位符位置；
5. **数据行绘制**（`地层列表` 逐层）：
   - 深度→图面比例：`totalDepth`=最后一行"进尺至(m)"；`realHeight`=gridHeight（≥5 层）或 `gridHeight/(dataRow+1)*dataRow`（<5 层压缩）；`scale = realHeight/totalDepth`；格顶 `yTop = ptInsert.y+offsetY+gridHeight`；
   - 每层要素：底部横线（至"土层描述"列止）→ 序号块（`序号.dwg`，地层编号"1-0-0"→"1"）→ 土层名称（"填土-素填土"→"素填土"）→ 高程 `elevation-toDepth` / 深度 `toDepth` / 厚度 `toDepth-prevBottom` 文本 → 土层描述 `AddDbMText`（超行自动画 `\_/` 折行线）→ 花纹填充（`pat_define.json` 岩性→图案，`PatHatchLoader::CreateHatchByName`）→ 取样线+编号 → 原位测试；
6. **标贯统计** `SPT_STAT`：按"杆长(m)"分组（浮点容差 0.001），组内记 min/max/总数，按组画击数线（横线 + `=总数` + `min-max` 文本）；重型动探画 `N63.5=击数` 符号；
7. **幂等**：块已存在则复用（`ImportDwgAsBlock` 已存在分支），重复执行不叠加实体。

### 0.4 剖面图现状设计（反推，`CCreateSectionView`）

**数据**：`project/剖面图参数.json` —— 顶层 `剖面组[]`，每组 `勘察组[]` = 孔号字符串数组；组内可选 `零标高`、`开挖标高`（数字）。**键名与网关 `SECTION_KEY_MAP`（sections→剖面组、holes→勘察组）一致**。

**流程**（每组剖面）：

1. **准备**：`prepare()` 读编录表；建 **14 个"地质-*"图层**（地面线、地层线、水位线、地层符号、填充花纹、钻孔、图框、图例、标贯、静探、标注栏、文字、地层编号、原位曲线）；`LoadAllLinetypesFromFile(support/cad.lin)` 载线型；`PatHatchLoader` 注册 `support/pat`；
2. **模板块**：`ImportDwgAsBlock(support/{CADYEAR}/钻孔剖面图.dwg, "钻孔剖面图")` 导入剖面图框模板；每组剖面插入一个块参照（`basePt` 逐组右移 430）；
3. **标注表格** `drawTable`：3 行表（动探击数 / 钻孔间距 (m) / 孔 深 (m)），"地质-标注栏"层；
4. **标尺比例尺** `drawRuler`：`divide=12` 格；`zk_divide = ceil((ceil(零标高)-min_zk_int)/12)`；`unitPerM = (height_ruler-10)/(divide*zk_divide)` —— **自动比例尺**（按孔底最底标高与零标高跨度算每米图面高度）；画刻度、标高文本与"(1985国家高程基准)/高 程 (m)"标题；返回 `SectionRulerInfo`（含 labelX/labelY 基准、mPerGrid、unitPerM）；
5. **钻孔柱状条** `drawColumn`：等分布点（柱宽 15、`width_per=(有效宽-46)/孔数`）；每孔按"孔口高程→孔底（终孔深度）"画柱线；"地质-文字"层写每层层底 `深度(标高)` 标注；"地质-填充花纹"层按地层名称逐层 hatch；
6. **固定线** `drawLineFix`：零标高线（`swx` 线型、色 5）+ 水位符号块 `support/block/GC.dwg`（块内占位符 `[number]` 替换为 `(标高)`）；开挖标高 →"基础底设计标高线"标注；
7. **地层连线** `drawLineDrill`：
   - 坐标映射 `getRuleHeight(rule, elev) = labelY + (elev - min_zk_int) * unitPerM`（标高→图面 Y）；
   - **地面线**：每孔柱左缘 `xL=x-15` → 柱右缘 `x` 连线（色 3）；
   - **地层线**：每孔柱内横线（`孔口高程-进尺至`→Y）+ **相邻孔跨孔连线**（A.x → B.xL）；同层直连，**缺层尖灭** `KsPinchElev`（参考下一层对应层高），B 有 A 无时反向尖灭；
   - **线型/颜色**：`CreateRandomPolylineStyles` 按地层编号去重分配"线型+颜色"（随机），同层跨孔统一；
8. **单孔支持**：`gpRows==1` 也画柱内横线（不强制 2 孔）。

**0.4.5 现状缺陷（运行时）**：`Debug/project/剖面图参数.json` 测试数据键名（`剖面条/孔号`）与代码期望（`剖面组/勘察组`）不一致，且引用的 ZK274 等不在编录表中 → 执行命令会 `aboutTrans` 空跑。**走网关正确落盘格式可运行**；修复 = 用网关格式生成测试参数或代码内做兼容映射（不属本次范围，但列入回归前置条件）。

## 1. 引言

### 1.1 背景与业务前提

**业务前提**：勘探项目平面图的底图 = **委托方（甲方）提供的现状场地总平面图（DWG 格式）**，图中已包含现状已有建筑物、道路、地形等场地要素，**并含拟建（规划）建筑轮廓**。勘探公司的职责是**在现成底图之上布设勘探点并生成勘探点平面布置图**，而非重新绘制底图。

当前插件生成"勘探点平面布置图"（`CCreatePlanView::Execute`）时只完成两件事：

1. **布孔**：读取 `project/钻探编录表.json`，按 `X坐标(m)/Y坐标(m)` 在"勘察点方案"图层插入钻孔图块（`support/block/GK*.dwg`），并写入钻孔编号、孔口高程、勘探深度文本；
2. **图例**：在"勘察点图例"图层绘制图例（勘探孔样例、地质剖面线及编号、已有/拟建建筑物样例块）。

**缺陷**：

- 缺少"底图导入"环节：委托方 DWG 底图没有自动导入/对齐环节，需人工粘贴或手动画；
- 缺少"出图比例"环节：无法按勘察出图惯例（如 1:500 / 1:1000）设定**成图比例**并据此对整体成图统一缩放；
- `PMYyjz.dwg / PMXnjz.dwg` 两个建筑物符号仅在图例中作样例块出现（`CreatePlanView.cpp` 第 476–550 行），**本版不参与底图要素绘制**（本版不重画底图内容，拟建轮廓由底图自带、随背景呈现）。

### 1.2 目标

参照**理正勘察**"流程二（有底图）"的出图思路，补齐"**底图导入 + 底图对齐 + 出图比例**"能力：

- **底图导入**：按配置自动导入委托方 DWG 底图（复用现有 `ImportDwgAsBlock`），底图以原始内容**整体作为一个块参照导入，系统不分解、不炸开、不修改该块及其内部图元图层；底图 DWG 只读**（BR-2），纳入独立图层便于置灰与开关；
- **底图对齐**：**默认按"底图坐标即钻孔坐标（同一坐标系、单位米）"处理，不施加对齐变换**；仅当配置 `registration` 两点配准（自动计算平移/旋转/缩放）或显式 `scale/rotation` 时才施加对齐（对应理正"底图初始化"的坐标设定，R7/FR-2.x）；
- **出图比例**：支持在"底图初始化"时设定**出图比例**（如 1:500），据此计算比例因子对**整体成图**统一缩放——底图几何、钻孔落点及成果要素按同一比例因子、绕同一基准缩放，作为图面比例尺/标注依据（R8/FR-3.x，详见第 6 章）；
- 与现有布孔、图例流程无缝集成，生成顺序为 **底图 → 钻孔 → 图例**，重复执行可整体重建（清旧层、重绘）；
- 兼容 AutoCAD 2005 / 2007 双版本编译环境；
- **完全兼容现有流程**：底图未配置或文件缺失时跳过底图，仅布孔 + 图例，不破坏现有出图。

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 勘探点平面布置图 | 岩土勘察成果图之一，展示钻孔（勘探点）在场地平面上的位置及场地环境 |
| 底图 | 委托方提供的现状场地总平面 DWG（含已有建筑、道路、地形），作为成果图的工作底图 |
| 底图初始化 | 理正术语：打开底图后设定**出图比例（比例因子）、坐标转换（配准）与图层匹配**的过程；本设计对应"**底图导入 + 底图对齐 + 出图比例**"（图层自动匹配不在本版范围） |
| 出图比例 | 底图初始化时设定的**成图比例**（如 1:500、1:1000）；据此计算比例因子对**整体成图**施加缩放，并作为图面比例尺/标注的依据。**区别于**用于**坐标对齐**的 `base_map.scale`（见第 6 章、BR-5） |
| 坐标对齐 scale | `base_map.scale` 或两点配准计算所得的缩放系数，用于**消除底图与钻孔的坐标系/单位差异**；同坐标系同单位时为 1.0 |

## 2. 理正流程与设计思路（设计依据）

### 2.1 理正平面图出图流程

理正勘察（北京理正工程地质勘察软件）平面图出图有两条标准流程：

- **流程一（无平面底图）**：先准备好勘探点表和剖面表数据，在 AutoCAD 中直接执行"生成平面图"命令，软件按数据自动布孔、标注、出图；
- **流程二（有平面底图）**：先打开已有的建筑总平面底图，执行**"底图初始化"**命令（设定**出图比例/比例因子**、**坐标转换（配准）**与图层匹配），再生成平面图，成果要素叠加在底图之上；
- **扩展能力**：支持多张底图并存、按线路方向自动分幅出图、旋转后重新生成；平面图可灵活布置投影剖线并自动计算钻孔桩号，可填绘地质内容，图例按标准图集生成。

**本项目属于典型"流程二"**：委托方提供底图 → 底图导入/初始化（含出图比例） → 布孔出图。

### 2.2 理正设计思路要点（提炼为本设计的依据）

1. **数据驱动**：勘探点表、剖面表是唯一数据源，出图是"数据 → 图形"的确定性映射，重复生成结果一致；
2. **底图与成果分离**：底图是独立于成果图的工作底图，先初始化（坐标/比例/图层对齐），再在其上叠加勘探点、剖面线、标注、图例等成果要素；**底图以原始内容整体作为一个块参照导入，系统不分解、不炸开、不修改该块及其内部图元图层，底图 DWG 只读**（BR-2）；
3. **图层分层管理**：底图整体纳入独立图层（便于置灰/冻结/打印控制），成果要素独立成层；
4. **符号标准化**：钻孔、建筑物等使用标准图块与图例；本版不提取、不统计、不标注建筑层数（图例文字按 P1-5 去掉"及层数"）；
5. **统一坐标与比例**：底图与成果图使用同一坐标基准（委托方总平面图一般即为当地坐标系）；**出图比例作用于整体成图**——底图几何、钻孔落点与成果要素按同一比例因子、绕同一基准统一缩放（详见第 6 章），使成图按该比例可正确打印，并作为图面比例尺/标注的依据。

### 2.3 现状差距对照

| 理正思路 | 本插件现状 | 差距 / 本次设计目标 |
| --- | --- | --- |
| 数据驱动出图 | 钻探编录表.json 驱动布孔 | 新增 plan_base.json 驱动"底图导入 + 出图比例"，统一数据驱动 |
| 底图初始化（导入+对齐） | 无，需人工粘贴底图 | 新增"底图 DWG 导入 + 插入/比例/旋转对齐 + **两点配准自动对齐**"（见 5.2） |
| 出图比例（比例因子） | 无 | 新增"出图比例"（成图比例），对整体成图统一缩放（见第 6 章） |
| 图层分层 | 勘察点方案 / 勘察点图例 两层 | 新增"底图-现状"图层（见 3.2） |
| 符号标准化 | 钻孔图块 + 图例已有 | 图例沿用（钻孔、建筑说明符号、剖面线）；建筑图例文字去掉"及层数" |
| 拟建/已有建筑 | 随底图自带呈现 | **本版不提取、不重画**，随底图背景呈现（原评审 P0-2 双线重叠问题自动消解） |

| base_map.scale | number | 否 | **坐标对齐**用插入比例（默认 1.0；仅用于消除底图与钻孔的坐标系/单位差异，同坐标系同单位时为 1.0）。**与 `plot_scale` 不同，见 4.4** |

| base_map.layer | string | 否 | 底图整体所在图层（默认"底图-现状"） |

| base_map.registration | object | 否 | **两点配准**（V0.3 新增）：底图上已知点 → 钻孔坐标对应点，自动计算平移/旋转/**坐标对齐缩放**并**覆盖** insert/scale/rotation；缺失时走手动参数 |
| base_map.registration.source_points | array | 配准时必填 | 底图（DWG 内部坐标）已知点，`[x,y]` 数组，1~2 个点（米） |
| base_map.registration.target_points | array | 配准时必填 | 源点在钻孔坐标系下的对应坐标，数量与 source_points 一致（米） |

### 4.3 坐标与单位约定

- 钻孔坐标单位为**米**（`钻探编录表.json` 的 `X坐标(m)/Y坐标(m)`）；
- 委托方底图 DWG 一般为当地坐标系（与勘察坐标同源）；**默认按"底图坐标即钻孔坐标（同一坐标系、单位米）"处理，即不施加任何对齐变换**（FR-2.1 / R7）；未配置任何对齐参数时日志输出"未配置对齐，默认按同一坐标系导入"；
- 仅当客户声明/配置不一致时：优先使用 **`registration` 两点配准**（给出底图上两个已知点（源）与钻孔坐标对应点（目标），插件自动算出平移+旋转+均匀缩放并回填导入参数）；两点配准不可用或未配置时，回退 `insert_x/y`、`scale`、`rotation` 手动参数；
- `plan_base.json` 缺失或解析失败时**跳过底图**，仅执行布孔+图例，完全兼容现有流程。

### 4.4 出图比例与坐标对齐 scale 的区别（BR-5）

| 项 | `base_map.scale` / registration 计算值 | `base_map.plot_scale` |
| --- | --- | --- |
| 用途 | **坐标对齐**：消除底图与钻孔的坐标系/单位差异 | **成图输出**：设定成图比例（如 1:500） |
| 同坐标系同单位时 | = 1.0 | 由出图比例决定 |
| 作用对象 | 仅底图（使其内部坐标落到钻孔坐标系） | **整体成图**（底图几何 + 钻孔落点 + 成果要素） |
| 与另一者关系 | 先执行（第一步） | 后执行（第二步），**串联、顺序固定、互不覆盖** |

**关键**：先按对齐参数完成坐标对齐，**再**按出图比例对整体成图统一缩放；底图块参照最终 `scale = 对齐scale × 出图比例因子`。出图比例**不会**覆盖对齐结果，二者耦合但各自独立。详见第 6 章。

## 6. 出图比例（底图初始化成图比例）设计

### 6.1 语义定义（用户已拍板）

- **出图比例 = 成图比例**（如 1:500）。配置项 `base_map.plot_scale` = 比例**分母** N（500 表示 1:500）。
- **作用于"整体成图"**：**底图几何随之缩放**（不是"只作用于注释/打印"）。即底图几何、钻孔落点及所有成果要素，按**同一比例因子、绕同一基准点**统一缩放。

### 6.2 与坐标对齐 scale 的区别（BR-5）

出图比例与坐标对齐是**两步、串联、顺序固定**：

```
原始底图坐标 p
  ──[第一步：坐标对齐 A]──▶  钻孔坐标 q = A(p) = T + s_align·R(θ_align)·p
  ──[第二步：出图比例 P]──▶  成图坐标 q' = P(q) = O + k_plot·(q − O)
```

- `s_align`（对齐 zoom）：来自 `registration` 或显式 `scale`，**坐标对齐**用，同坐标系同单位时 = 1.0；
- `k_plot`（出图比例因子）：**成图输出**用，由 `plot_scale` 换算；
- **二者互不覆盖**：底图块参照最终 `scale = s_align × k_plot`。

### 6.3 统一缩放（保证底图与钻孔不错位）—— 核心约束

**CRITICAL**：底图几何与钻孔落点、以及所有成果要素，必须按**同一比例因子、绕同一基准 O**统一缩放，**绝不允许"只缩底图、不缩钻孔"导致两者错位**。

设基准点 O（默认坐标原点 (0,0)），出图比例因子 `k_plot`，则：

| 对象 | 变换 |
| --- | --- |
| 底图块参照 | `position = O + k_plot·(T − O)`；`scaleFactors = s_align × k_plot`；`rotation = θ_align` |
| 钻孔块参照 | `position = O + k_plot·(p_hole − O)`；`scaleFactors = k_plot`（符号尺寸随比例） |
| 图例及其他成果图元 | 位置/尺寸按同一变换 P 缩放 |
| 钻孔 X/Y 标注文字 | **内容 = 编录真实坐标值（不随几何缩放）**；文字位置随 P 变换 |

**不错位证明**：底图内位于钻孔坐标 q 的要素经 A 后得 q，再经 P 得 `P(q)`；钻孔落点为真实钻孔坐标 q，经 P 得 `P(q)`。二者经同一 P 变换落在同一点，**天然重合、不会错位**。

### 6.4 参数与默认

| 项 | 值 | 说明 |
| --- | --- | --- |
| `plot_scale` | 空/未配置 | `k_plot = 1.0`，**不施加出图比例缩放，与现状一致**（FR-3.1） |
| `plot_scale` | 正整数 N | `k_plot = 1000 / N`（默认约定，见 6.5）；日志输出所用比例与比例因子 |
| `plot_scale` | ≤0 或非数字 | 打印告警，回退 `k_plot = 1.0`，不阻断 |
| 基准点 O | (0,0) | 统一缩放中心；如需可后续以配置覆盖 |

### 6.5 比例因子换算约定（**待客户确认**）

- **默认约定**：底图/坐标按真实坐标 **1 单位 = 1 米** 建模；出图比例因子 `k_plot = 1000 / N`，含义为把"米"换算为"图面毫米（1 单位 = 1 毫米）"，使成图在 1:1 打印下即为 1:N（N=1000 → `k_plot=1.0`，与"1:1000 基线"一致；N=500 → `k_plot=2.0`）。
- **待客户确认点（呼应《需规》§5.3-3 /《需求文档》§4.3 待确认）**：
  1. 出图比例的**准确语义**——是否应对**底图整体施加缩放**，还是仅作为**图面比例尺依据**（不改变底图几何）？本版按前者（整体缩放）实现；
  2. **比例因子换算**与底图绘图单位约定相关（见《需规》§5.4 /《需求文档》§2.4），最终以客户确认为准。

### 6.6 兼容性（AutoCAD 2005 / 2007）

- 统一缩放仅涉及块参照的 `setPosition` / `setScaleFactors` / `setRotation` 与已有图元的矩阵变换，均为两版本基础 API；
- 若采用遍历模型空间对既有图元施加变换矩阵的实现，须用 `AcDbEntity::transformBy`（两版本均可用）；对块参照可用 `setScaleFactors`/`setPosition` 直接设置，避免二次变换。

## 7. 集成设计

### 7.1 `CCreatePlanView::Execute()` 流程改造

改造后顺序：

```
prepare()                                  // 原有：读取钻探编录表.json
LoadJsonFile(support/block_define.json)    // 原有
ClearSelection() / startTrans() / actionBefore()   // 原有
DrawBaseMap()                              // ★ 新增：导入底图（含对齐，默认不施加变换），内部先清旧底图层
EnsureLayer("勘察点方案") + 清旧 → 布孔     // 原有（按真实坐标插入）
CreateLegend()                             // 原有（图例文字按 P1-5 去"及层数"）
ApplyPlotScale(m_plotScale)                // ★ 新增：出图比例——对本命令成果图层统一缩放（详见第 6 章）
commitTrans() / actionEnd() / regen()      // 原有
```

- `DrawBaseMap()` 失败（未配置/文件缺失/解析失败）时打印告警并继续布孔，**不阻断**主流程；
- `plot_scale` 未配置/非法时不缩放，与现状一致；
- 底图绘制与布孔、图例同处一个事务（`startTrans` 之后），保证"一键生成"整体可回滚；
- 重复执行时 `EraseBaseMapLayers()` 清空"底图-现状"图层与旧底图块 → 重建（与布孔、图例的清旧重建一致）。

> **顺序要点**：出图比例缩放必须放在**布孔与图例都完成之后**（对本命令全部成果图层一次性施加同一矩阵：`底图-现状 / 勘察点方案 / 勘察点图例`），从而保证"底图/钻孔/图例"三者不错位；绝不能在底图或钻孔阶段分别、以不同参数缩放。具体落点在详设中细化。

### 7.2 HTTP 网关接口设计（一次性无状态，`cad_server/draw_gateway.py`）

> **V0.6 修订**：接口由"项目制多接口"（V0.5）**改回一次性无状态调用**——**系统不记录任何项目信息**（无项目编码、无项目目录、无镜像机制）。三个生成接口分开，数据随调用携带：**柱状图/剖面图携带勘探数据，平面图额外携带底图（DWG 文件上传或可访问链接二选一）+ 可选平面图配置**。**参数一律放请求参数，路径不放参数。**
>
> **V0.7 修订**：落实评审 **P0-4**（**插件端不联网**；底图 URL 下载由**网关端**完成，校验扩展名与大小后落盘）、**P0-5**（网关侧声明**单项目/单 CAD 实例**部署假设）、**P2**（三接口 `/api/draw/column|section|plan` **本版待实现**——现状 `draw_gateway.py:184` 仍为**单接口 `/api/draw`**）。
>
> ⚠️ **实现状态**：本节描述的是**目标需求**（对应《需求文档》V2.3 §4.6 FR-6.x），非现状能力；现网关与代码仍为单接口 `/api/draw`。

#### 7.2.1 接口清单

| # | 接口 | 方法 | 用途 | 携带参数 |
| --- | --- | --- | --- | --- |
| 1 | `/api/draw/column` | POST | **生成柱状图** | multipart/form：`borehole_data`（勘探数据）、可选 `auto_zoom` |
| 2 | `/api/draw/section` | POST | **生成剖面图** | multipart/form：`borehole_data`、可选 `section_params`（剖面参数）、可选 `auto_zoom` |
| 3 | `/api/draw/plan` | POST | **生成平面图** | multipart/form：`borehole_data`、**底图**（`base_map` DWG 文件 或 `base_map_url` 可访问链接，二选一）、可选 `plan_base`（平面图配置，英文 key 透传）、可选 `auto_zoom` |

> 三个接口分别对应现有 `VIEW_ROUTES`：`plan→/ai/feature/create_plan_view`、`column→/ai/feature/create_column_view`、`section→/ai/feature/create_section_view`；调用前由网关把本次数据落盘插件标准位置（见 7.2.3），插件侧命令与数据读取零改动。

#### 7.2.2 调用参数说明

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `borehole_data` | 是 | 勘探数据（英文结构，网关转中文键落盘 `project/钻探编录表.json`），三图共用 |
| `base_map` / `base_map_url` | 否 | 底图二选一：multipart 文件上传（限 .dwg、≤50MB）或可访问链接（仅 http/https，**由网关端下载**后校验 .dwg 与大小）；均不提供时平面图降级为仅布孔+图例 |
| `section_params` | 否 | 剖面参数（网关转中文键落盘 `project/剖面图参数.json`） |
| `plan_base` | 否 | 平面图配置（英文 key 原样落盘 `project/plan_base.json`：底图对齐参数与**出图比例** `plot_scale`） |
| `auto_zoom` | 否 | 出图后是否自动缩放到全图（默认 true） |

#### 7.2.3 网关处理流程（一次性，无状态）

```
POST /api/draw/<view>
 1. 校验参数（borehole_data 必填；底图文件/URL 校验）
 2. 底图：文件保存 或 URL 下载 → support/底图/{safe_name}.dwg（仅取文件名、限 .dwg、限大小）
 3. 落盘插件标准位置：project/钻探编录表.json、project/剖面图参数.json、project/plan_base.json
    （plan_base.json 内 base_map.dwg 指向 2 中保存的底图路径）
 4. _lock 内调用 _call_cad(VIEW_ROUTES[view])  →  出图
 5. 可选 auto_zoom
 6. 返回 {status, results, errors}；不保留任何项目状态
```

#### 7.2.4 工作流时序（典型）

```
① POST /api/draw/column   {borehole_data}                                     → 柱状图
② POST /api/draw/section  {borehole_data, section_params}                     → 剖面图
③ POST /api/draw/plan     {borehole_data, base_map(上传 DWG 文件), plan_base} → 平面图（底图+出图比例+布孔+图例）
④ POST /api/draw/plan     {borehole_data, base_map_url(可访问链接), plan_base} → 平面图（底图来自链接）
```

#### 7.2.5 兼容与安全

| 项 | 设计 |
| --- | --- |
| 无状态 | 系统不保存项目目录/元信息/编码；每次调用独立落盘标准位置（覆盖上次），调用结束不保留 |
| **单项目/单 CAD 实例**（FR-6.5） | 本系统按"**同一时刻仅服务一个项目、一个 CAD 实例**"部署；落盘路径固定，后调用覆盖前调用；多项目并行须由部署层保证串行或按项目分目录，**本版不承诺多项目数据隔离** |
| 旧接口 | `/api/draw`（一次性全量、无项目模式）被三个独立接口取代；如需兼容保留同一实现（共用 `_write_json` / `_translate_*` / `_call_cad` / `_lock`） |
| 文件安全 | 底图 `os.path.basename` 取文件名防路径穿越；限 `.dwg` 扩展名；体积上限 50MB |
| URL 安全（P0-4） | **仅网关端**允许 http/https（拒绝 file:// 等）；下载后校验扩展名与大小；超时与下载失败明确报错；**插件端不联网** |
| 并发 | 落盘与生成全程 `_lock` 串行；并发调用排队 |
| 只读原则 | 底图 DWG 与编录数据只读，生成过程不修改源文件 |
| 响应 | 统一 `{status, results, errors}`；生成接口返回对应视图调用结果 |

不变：仍为"一键平面图"（`_SLPlanView`），无需新增命令。

## 8. 异常与边界处理

| 场景 | 处理 |
| --- | --- |
| plan_base.json 不存在 / 解析失败 | 打印 `[CAD ERROR] 未找到底图配置，跳过底图`，继续布孔+图例（兼容现状） |
| base_map.dwg 路径为空 / 文件不存在 | 跳过底图导入，打印提示 |
| base_map.dwg 读取失败（版本过低/损坏） | `ImportDwgAsBlock` 返回 kNull → 跳过，打印错误码 |
| 未配置任何对齐参数（默认行为，FR-2.1） | 按"底图坐标即钻孔坐标（同坐标系、米）"导入，不施加变换；日志"未配置对齐，默认按同一坐标系导入" |
| 底图与钻孔坐标系不一致 | 配置 `registration` 两点配准自动对齐，或显式 insert/scale/rotation 校准 |
| registration 点数不匹配 / 两点过近 / 计算非法 | 打印告警，回退手动 insert/scale/rotation，导入不中断 |
| `plot_scale` 未配置 | 不施加出图比例缩放，与现状一致 |
| `plot_scale` ≤0 / 非数字 | 打印告警，回退 `k_plot = 1.0`（不缩放），不阻断 |
| 出图比例导致位移/缩放 | 严格执行"同因子、同基准统一缩放"（第 6.3 节），底图与钻孔不错位 |
| 底图块名已存在（重复执行） | 先 `EraseBlock("委托方底图")` 删除旧块定义与参照，再重新导入（避免"块已存在不插参照"导致底图缺失） |
| 重复执行"一键平面图" | 先 `EraseBaseMapLayers()` + `EraseBlock("委托方底图")` → 重建 |
| `plan_base.json` 内含已删除键（proposed_layer/shadow/proposed_buildings） | 解析时忽略、不报错（向后兼容旧文件） |
