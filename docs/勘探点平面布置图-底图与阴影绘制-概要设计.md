### 0.3 柱状图现状设计（反推，`CCreateColumnView`）

**成图模式：模板块 + 占位符替换**（非逐元素几何绘制表头）：

1. **逐孔布局**：遍历 `s_pJsonData` 顶层（每孔一个模板块实例）；孔间距 `space=222.6865`，逐孔 `ptInsert.x += space` 右移；每 10 孔泵消息防卡死；
2. **模板导入**：`ImportDwgAsBlock(support/{CADYEAR}/钻孔柱状图.dwg, ptInsert, arrayName)`，块名 = 钻孔编号；
3. **占位符替换** `CollectTexts`：遍历块定义内单行文本，识别 `[xxx]` 占位符，经 `s_fieldMap`（15 项）映射表取值替换：

| 占位符 | 数据源 | 占位符 | 数据源 |
| --- | --- | --- | --- |
| [page_no] / [page_count] | 当前页 / 总页码 | [coordinate_x] / [coordinate_y] | X/Y坐标（加 `x=`/`y=` 前缀） |
| [project_name] / [project_no] | 工程名称 / （预留） | [start_date] / [completion_date] | 开孔 / 终孔日期 |
| [hole_no] | 钻孔编号 | [water_depth] | 稳定水位(m) |
| [elevation] | 孔口高程(m) | [survey_unit] | 公司名称 |
| [diameter] | `JsonConfig.profile.HOLE_DIAMETER_ZK` | [mapping] / [check] | 制图人 / 校对人（块，见下） |

4. **[mapping]/[check] 特殊处理** `CollectMapping`：在占位符位置插入 `support/{CADYEAR}/制图人.dwg / 校对人.dwg` 块参照，并按包围盒**非等比缩放到 23×8**（`sx=23/w, sy=8/h`），对齐占位符位置；
5. **数据行绘制**（`地层列表` 逐层）：
   - 深度→图面比例：`totalDepth`=最后一行"进尺至(m)"；`realHeight`=gridHeight（≥5 层）或 `gridHeight/(dataRow+1)*dataRow`（<5 层压缩）；`scale = realHeight/totalDepth`；格顶 `yTop = ptInsert.y+offsetY+gridHeight`；
   - 每层要素：底部横线（至"土层描述"列止）→ 序号块（`序号.dwg`，地层编号"1-0-0"→"1"）→ 土层名称（"填土-素填土"→"素填土"）→ 高程 `elevation-toDepth` / 深度 `toDepth` / 厚度 `toDepth-prevBottom` 文本 → 土层描述 `AddDbMText`（超行自动画 `\_/` 折行线）→ 花纹填充（`pat_define.json` 岩性→图案，`PatHatchLoader::CreateHatchByName`）→ 取样线+编号 → 原位测试；
6. **标贯统计** `SPT_STAT`：按"杆长(m)"分组（浮点容差 0.001），组内记 min/max/总数，按组画击数线（横线 + `=总数` + `min-max` 文本）；重型动探画 `N63.5=击数` 符号；
7. **幂等**：块已存在则复用（`ImportDwgAsBlock` 已存在分支），重复执行不叠加实体。

### 0.4 剖面图现状设计（反推，`CCreateSectionView`）

**数据**：`project/剖面图参数.json` —— 顶层 `剖面组[]`，每组 `勘察组[]` = 孔号字符串数组；组内可选 `零标高`、`开挖标高`（数字）。**键名与网关 `SECTION_KEY_MAP`（sections→剖面组、holes→勘察组）一致**。

**流程**（每组剖面）：

1. **准备**：`prepare()` 读编录表；建 **14 个"地质-*"图层**（地面线、地层线、水位线、地层符号、填充花纹、钻孔、图框、图例、标贯、静探、标注栏、文字、地层编号、原位曲线）；`LoadAllLinetypesFromFile(support/cad.lin)` 载线型；`PatHatchLoader` 注册 `support/pat`；
2. **模板块**：`ImportDwgAsBlock(support/{CADYEAR}/钻孔剖面图.dwg, "钻孔剖面图")` 导入剖面图框模板；每组剖面插入一个块参照（`basePt` 逐组右移 430）；
3. **标注表格** `drawTable`：3 行表（动探击数 / 钻孔间距 (m) / 孔 深 (m)），"地质-标注栏"层；
4. **标尺比例尺** `drawRuler`：`divide=12` 格；`zk_divide = ceil((ceil(零标高)-min_zk_int)/12)`；`unitPerM = (height_ruler-10)/(divide*zk_divide)` —— **自动比例尺**（按孔底最底标高与零标高跨度算每米图面高度）；画刻度、标高文本与"(1985国家高程基准)/高 程 (m)"标题；返回 `SectionRulerInfo`（含 labelX/labelY 基准、mPerGrid、unitPerM）；
5. **钻孔柱状条** `drawColumn`：等分布点（柱宽 15、`width_per=(有效宽-46)/孔数`）；每孔按"孔口高程→孔底（终孔深度）"画柱线；"地质-文字"层写每层层底 `深度(标高)` 标注；"地质-填充花纹"层按地层名称逐层 hatch；
6. **固定线** `drawLineFix`：零标高线（`swx` 线型、色 5）+ 水位符号块 `support/block/GC.dwg`（块内占位符 `[number]` 替换为 `(标高)`）；开挖标高 →"基础底设计标高线"标注；
7. **地层连线** `drawLineDrill`：
   - 坐标映射 `getRuleHeight(rule, elev) = labelY + (elev - min_zk_int) * unitPerM`（标高→图面 Y）；
   - **地面线**：每孔柱左缘 `xL=x-15` → 柱右缘 `x` 连线（色 3）；
   - **地层线**：每孔柱内横线（`孔口高程-进尺至`→Y）+ **相邻孔跨孔连线**（A.x → B.xL）；同层直连，**缺层尖灭** `KsPinchElev`（参考下一层对应层高），B 有 A 无时反向尖灭；
   - **线型/颜色**：`CreateRandomPolylineStyles` 按地层编号去重分配"线型+颜色"（随机），同层跨孔统一；
8. **单孔支持**：`gpRows==1` 也画柱内横线（不强制 2 孔）。

**0.4.5 现状缺陷（运行时）**：`Debug/project/剖面图参数.json` 测试数据键名（`剖面条/孔号`）与代码期望（`剖面组/勘察组`）不一致，且引用的 ZK274 等不在编录表中 → 执行命令会 `aboutTrans` 空跑。**走网关正确落盘格式可运行**；修复 = 用网关格式生成测试参数或代码内做兼容映射（不属本次范围，但列入回归前置条件）。

## 1. 引言

### 1.1 背景与业务前提

**业务前提**：勘探项目平面图的底图 = **委托方（甲方）提供的现状场地/村子总平面图（DWG 格式）**，图中已包含现状已有建筑物、道路、地形等场地要素。勘探公司的职责是**在现成底图之上布设勘探点并生成勘探点平面布置图**，而非重新绘制底图。

当前插件生成"勘探点平面布置图"（`CCreatePlanView::Execute`）时只完成两件事：

1. **布孔**：读取 `project/钻探编录表.json`，按 `X坐标(m)/Y坐标(m)` 在"勘察点方案"图层插入钻孔图块（`support/block/GK*.dwg`），并写入钻孔编号、孔口高程、勘探深度文本；
2. **图例**：在"勘察点图例"图层绘制图例（勘探孔样例、地质剖面线及编号、已有/拟建建筑物样例块）。

**缺陷**：

- 缺少"底图导入"环节：委托方 DWG 底图没有自动导入/对齐环节，需人工粘贴或手动画；
- 拟建建筑物（现状底图中不存在）的轮廓与"影子"（阴影）效果没有绘制；
- `PMYyjz.dwg / PMXnjz.dwg` 两个建筑物符号仅在图例中作样例块出现（`CreatePlanView.cpp` 第 476–550 行），未参与实际底图要素绘制。

### 1.2 目标

参照**理正勘察**"流程二（有底图）"的出图思路，补齐"底图导入 + 拟建建筑阴影"能力：

- **底图导入**：按配置自动导入委托方 DWG 底图（复用现有 `ImportDwgAsBlock`），支持插入位置/比例/旋转对齐，纳入独立图层便于置灰与开关；底图与钻孔坐标错位时，支持 **`registration` 两点配准自动计算对齐参数**（对应理正"底图初始化"的坐标设定）；
- **拟建建筑绘制**：拟建建筑轮廓**直接从委托方底图 DWG 按图层提取**（总平面图惯例画在专门图层，如"拟建建筑"），自动绘制粗线轮廓 + 右下方"影子"（阴影），与图例符号（PMXnjz）一致；未配置提取图层或提取失败时，可用 `proposed_buildings`（JSON 轮廓）兜底；
- 与现有布孔、图例流程无缝集成，重复执行可整体重建（清旧层、重绘）；
- 兼容 AutoCAD 2005 / 2007 双版本编译环境；
- **完全兼容现有流程**：底图未配置或文件缺失时跳过底图，仅布孔 + 图例，不破坏现有出图。

### 1.3 术语

| 术语 | 说明 |
| --- | --- |
| 勘探点平面布置图 | 岩土勘察成果图之一，展示钻孔（勘探点）在场地平面上的位置及场地环境 |
| 底图 | 委托方提供的现状场地/村子总平面 DWG（含已有建筑、道路、地形），作为成果图的工作底图 |
| 底图初始化 | 理正术语：打开底图后设定坐标基准、出图比例、图层匹配的过程；本设计对应"底图导入 + 对齐参数" |
| 拟建建筑物 | 现状底图中不存在的待建建筑，轮廓由设计/勘察方提供，需单独绘制并加影子 |
| 影子 / 阴影 | 拟建建筑物轮廓的投影效果（偏移轮廓线或灰色 SOLID 填充），用于区分拟建与已有建筑 |

## 2. 理正流程与设计思路（设计依据）

### 2.1 理正平面图出图流程

理正勘察（北京理正工程地质勘察软件）平面图出图有两条标准流程：

- **流程一（无平面底图）**：先准备好勘探点表和剖面表数据，在 AutoCAD 中直接执行"生成平面图"命令，软件按数据自动布孔、标注、出图；
- **流程二（有平面底图）**：先打开已有的建筑总平面底图，执行**"底图初始化"**命令（设定坐标基准、出图比例、图层匹配），再生成平面图，成果要素叠加在底图之上；
- **扩展能力**：支持多张底图并存、按线路方向自动分幅出图、旋转后重新生成；平面图可灵活布置投影剖线并自动计算钻孔桩号，可填绘地质内容，图例按标准图集生成。

**本项目属于典型"流程二"**：委托方提供底图 → 底图导入/初始化 → 布孔出图。

### 2.2 理正设计思路要点（提炼为本设计的依据）

1. **数据驱动**：勘探点表、剖面表是唯一数据源，出图是"数据 → 图形"的确定性映射，重复生成结果一致；
2. **底图与成果分离**：底图是独立于成果图的工作底图，先初始化（坐标/比例/图层对齐），再在其上叠加勘探点、剖面线、标注、图例等成果要素；**底图本身不重绘、不修改**；
3. **图层分层管理**：底图整体纳入独立图层（便于置灰/冻结/打印控制），成果要素独立成层；
4. **符号标准化**：钻孔、建筑物等使用标准图块与图例，并携带属性（编号、高程、深度、层数），图形与数据可双向对应；
5. **统一坐标与比例**：底图与成果图使用同一坐标基准（委托方总平面图一般即为当地坐标系），出图比例决定标注、图例、线宽的尺寸体系。

### 2.3 现状差距对照

| 理正思路 | 本插件现状 | 差距 / 本次设计目标 |
| --- | --- | --- |
| 数据驱动出图 | 钻探编录表.json 驱动布孔 | 新增 plan_base.json 驱动"底图导入 + 拟建建筑"，统一数据驱动 |
| 底图初始化（导入+对齐） | 无，需人工粘贴底图 | 新增"底图 DWG 导入 + 插入/比例/旋转对齐 + **两点配准自动对齐**"（见 5.2） |
| 图层分层 | 勘察点方案 / 勘察点图例 两层 | 新增"底图-现状 / 底图-拟建建筑物 / 底图-拟建阴影"图层（见 3.2） |
| 符号标准化 | 钻孔图块 + 图例已有 | 拟建建筑轮廓绘制与图例符号（PMXnjz）对应 |
| 拟建建筑阴影 | 无 | 新增阴影生成（见第 6 章）；轮廓来源 = 底图拟建图层提取（首版），JSON 兜底 |

### 3.2 图层设计

| 图层名 | 颜色(ACI) | 线宽(mm) | 线型 | 用途 / 要素 |
| --- | --- | --- | --- | --- |
| 底图-现状 | 8（灰）或 253 | 按底图原样 | 按底图原样 | 委托方底图整体（导入的块参照；置灰便于成果要素突出） |
| 底图-拟建建筑物 | 7（白/黑） | 0.75 | 实线 | 拟建建筑物轮廓（粗线，总图制图标准） |
| 底图-拟建阴影 | 253（浅灰） | 0.18 | 实线/SOLID | 拟建建筑物影子（填充或偏移轮廓） |
| 勘察点方案 | 现有 | 现有 | 现有 | 钻孔图块（不动） |
| 勘察点图例 | 现有 | 现有 | 现有 | 图例（不动） |

> 说明：
> 1. 已有建筑物、道路等现状要素**位于底图 DWG 内部**，不为其新建图层；
> 2. 底图导入为"块参照"整体（图层：底图-现状），颜色可整体置灰（若块内实体颜色为 ByLayer，则随图层变色；若为显式颜色则需在导入时重设或接受原色，见 5.2 说明）；
> 3. 图层命名与 `EnsureLayer` 现有机制一致，重复执行先 `EraseLayerEntities` 清旧再重建。

### 3.3 绘制顺序（Z 序）

底图在下、成果在上，保证打印与视觉层次正确：

```
① 底图-现状（委托方底图，最底，置灰）
② 底图-拟建阴影（SOLID 填充）
③ 底图-拟建建筑物（粗线，覆盖在自身阴影之上）
④ 勘察点方案（钻孔符号）
⑤ 勘察点图例（最顶，位于图纸底部区域）
```

绘制顺序天然由"先画在下、后画在上"保证，必要时用 `AcDb::kDrawOrder` 显式设置。

### 4.3 坐标与单位约定

- 钻孔坐标单位为**米**（`钻探编录表.json` 的 `X坐标(m)/Y坐标(m)`）；
- 委托方底图 DWG 一般为当地坐标系（与勘察坐标同源），**默认插入 (0,0)、比例 1.0、旋转 0** 即与钻孔对齐；
- 若底图坐标系与钻孔不一致（单位不同/平移错位/旋转差异），优先配置 **`registration` 两点配准**：给出底图上两个已知点（源）与钻孔坐标对应点（目标），插件自动算出平移+旋转+均匀缩放并回填导入参数（**首版能力**，对应理正"底图初始化"）；两点配准不可用或未配置时，回退 `insert_x/y`、`scale`、`rotation` 手动参数；
- `plan_base.json` 缺失或解析失败时**跳过底图**，仅执行布孔+图例，完全兼容现有流程。

## 6. 阴影（影子）绘制设计

### 6.1 行业做法

按《总图制图标准》(GB/T 50103) 及勘察行业通行画法：

- **拟建建筑物**：粗实线轮廓（醒目、表示待建主体）；
- **已有建筑物**：位于委托方底图内，细线/置灰表示现状环境，不重绘；
- 拟建建筑常附加"影子"：即轮廓向固定方向偏移一段距离后形成的轮廓（影子线）或用灰色填充，形成立体投影感，便于从平面上一眼区分拟建与已有。

### 6.2 推荐方案（现行）

采用"**平移轮廓 + SOLID 填充**"：

```
对每个拟建建筑物轮廓 P = {p0, p1, ..., pn}（闭合，n≥3）：
  1. 影子轮廓 S = 将 P 整体平移 (shadow.dx, shadow.dy)，仍为闭合多边形
  2. 用 S 创建闭合 AcDbPolyline
  3. 创建 AcDbHatch，pattern = SOLID，color = 253（浅灰），layer = 底图-拟建阴影
  4. appendLoop(kExternal, polyline) 添加边界，评估并入库
  5. 用 P 创建闭合 AcDbPolyline，lineweight = 0.75mm，layer = 底图-拟建建筑物
```

**几何说明**：影子用"整体平移"而非"等距偏移"（`getOffsetCurves`）。平移不产生自交、无需判断偏移方向，对矩形/正交建筑完全够用；等距偏移算法在凹多边形上可能自交，首版不引入。

**轮廓来源（V0.4）**：拟建建筑轮廓 P 取自**底图 DWG 拟建图层提取**（闭合多段线，见 5.2 `ExtractProposedFromBaseMap`）或 **JSON `proposed_buildings` 兜底**；两者经同一套"阴影 → 粗线"绘制，视觉一致。

### 6.3 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| shadow.dx | 1.5（米） | 影子 X 向偏移（向右） |
| shadow.dy | -1.5（米） | 影子 Y 向偏移（向下，右下方投影，符合常规"右下方光源"习惯） |
| 阴影颜色 | 253（浅灰） | 打印呈浅灰，不抢主体 |
| 拟建轮廓线宽 | 0.75 mm | 粗线 |

### 6.4 兼容性（AutoCAD 2005 / 2007）

- `AcDbHatch::appendLoop` 在两版本均可用，但 2005 对 SOLID 填充边界要求闭合且不自交，V0.1 的平移轮廓天然满足；
- **退化方案**：若实测某版本 SOLID 填充出现兼容问题，改为"影子 = 平移轮廓细线"（图层：底图-拟建阴影，线型实线，颜色 253，线宽 0.18mm），视觉效果仍能区分拟建/已有，实现更简单；
- 项目已有 `PatHatchLoader.cpp`（14KB，柱状图土层图案加载），若后续需要图案填充（如散点/斜线影子），可复用其模式加载逻辑。

## 7. 集成设计

### 7.1 `CCreatePlanView::Execute()` 流程改造

改造后顺序：

```
prepare()                                  // 原有：读取钻探编录表.json
LoadJsonFile(support/block_define.json)    // 原有
ClearSelection() / startTrans() / actionBefore()   // 原有
DrawBaseMap()                              // ★ 新增：导入底图 + 拟建建筑阴影，内部先清旧底图层
EnsureLayer("勘察点方案") + 清旧 → 布孔     // 原有
CreateLegend()                             // 原有
commitTrans() / actionEnd() / regen()      // 原有
```

- `DrawBaseMap()` 失败（未配置/文件缺失/解析失败）时打印告警并继续布孔，**不阻断**主流程；
- 底图绘制与布孔同处一个事务（`startTrans` 之后），保证"一键生成"整体可回滚；
- 重复执行时 `EraseBaseMapLayers()` 清空"底图-*"图层 → 重建（与布孔、图例的清旧重建一致）。

### 7.2 HTTP 网关接口设计（项目制，`cad_server/draw_gateway.py`）

> **V0.5 修订**：接口由"一次性携带全部数据（`/api/draw`）"升级为**项目制多接口**——**项目编码为唯一索引**：创建项目（含底图上传）→ 上传勘探数据 → 三个生成接口分开调用（柱状图 / 平面图 / 剖面图），每次调用仅凭项目编码定位数据。

#### 7.2.1 接口清单

> **设计约定**：**路径中不放参数**（不使用 `/api/project/{code}/...` 形式）；`project_code` 一律放在**请求参数**中（创建接口在 multipart form，其余在 **query 参数** `?project_code=xxx`），数据体放 body。

| # | 接口 | 方法 | 用途 | 参数位置 |
| --- | --- | --- | --- | --- |
| 1 | `/api/project` | POST | **创建项目**：上传项目信息 + 委托方底图 | multipart form：`project_code`、`project_name`、`dwg`（可选） |
| 2 | `/api/project/borehole` | PUT | 上传/更新**勘探数据** | query `project_code` + body `borehole_data`（英文结构，网关转中文落盘） |
| 3 | `/api/project/section_params` | PUT | 上传/更新**剖面图参数**（可选） | query `project_code` + body `section_params` |
| 4 | `/api/project/plan_base` | PUT | 上传/更新**平面图配置**（可选） | query `project_code` + body `plan_base`（英文 key，透传落盘） |
| 5 | `/api/draw/plan` | POST | **生成平面图** | query `project_code`（+ 可选 body `auto_zoom`） |
| 6 | `/api/draw/column` | POST | **生成柱状图** | query `project_code`（+ 可选 body `auto_zoom`） |
| 7 | `/api/draw/section` | POST | **生成剖面图** | query `project_code`（+ 可选 body `auto_zoom`） |
| 8 | `/api/project` | GET | 查询项目状态与文件清单 | query `project_code` |
| 9 | `/api/project` | DELETE | 删除项目（可选） | query `project_code` |

> 三个生成接口分别对应现有 `VIEW_ROUTES`：`plan→/ai/feature/create_plan_view`、`column→/ai/feature/create_column_view`、`section→/ai/feature/create_section_view`；调用前由网关同步项目数据镜像（见 7.2.3），插件侧命令与数据读取零改动。

#### 7.2.2 数据布局（项目目录隔离）

```
project/
├── {project_code}/              # 唯一索引目录（字符白名单校验，防路径注入）
│   ├── project.json             # 元信息：project_code / project_name / created_at / 底图路径
│   ├── 钻探编录表.json          # 勘探数据（网关转中文键）
│   ├── 剖面图参数.json          # 剖面参数（可选）
│   ├── plan_base.json           # 平面图配置（可选，英文 key 原样）
│   └── 底图/{原文件名}.dwg      # 上传的委托方底图
└── （标准位置 project/ 及 support/ 为"活动项目镜像"，见 7.2.3）
```

#### 7.2.3 插件侧定位机制（三图代码零改动）

三图命令 `prepare()` 固定读 `project/钻探编录表.json`（无项目参数）。为保持柱状图/剖面图"仅回归不动"、平面图增强不改数据读取：

- **全量存储**：所有项目文件保存在 `project/{project_code}/`（项目目录隔离，编码为唯一索引）；
- **活动项目镜像**：网关在每次**上传/生成**调用时，把该项目文件同步（覆盖）到插件标准位置 `project/钻探编录表.json`、`project/剖面图参数.json`、`project/plan_base.json`，并把底图复制到 `support/底图/`；随后再调 `_call_cad(VIEW_ROUTES[...])`；
- 标准位置始终是"最近一次操作项目的镜像"，插件行为完全不变；多项目并存互不干扰。

#### 7.2.4 工作流时序（典型）

```
① POST /api/project                          → 建 project/{code}/、存 project.json、存底图 → 同步镜像
② PUT  /api/project/borehole?project_code=x  → 英文→中文落盘 project/{code}/钻探编录表.json → 同步镜像
③ PUT  /api/project/plan_base?project_code=x（可选）→ 透传落盘 project/{code}/plan_base.json → 同步镜像
④ POST /api/draw/column?project_code=x       → 同步镜像 → _call_cad(create_column_view)   # 柱状图
⑤ POST /api/draw/plan?project_code=x         → 同步镜像(含底图) → _call_cad(create_plan_view) # 平面图
⑥ POST /api/draw/section?project_code=x      → 同步镜像 → _call_cad(create_section_view)  # 剖面图
```

#### 7.2.5 兼容与安全

| 项 | 设计 |
| --- | --- |
| 旧接口兼容 | `/api/draw`（一次性全量）保留为"无项目模式"：直接写标准位置后出图；与项目制接口共用 `_write_json` / `_translate_*` / `_call_cad` / `_lock` |
| 项目编码校验 | `^[A-Za-z0-9_-]{1,64}$` 白名单校验（编码将用作目录名，**必须防路径注入**）；重复创建返回已存在错误或允许覆盖（按需求配置） |
| 上传校验 | 底图限 DWG（扩展名 + 魔数/打开验证）；体积上限（如 50MB）；文件落盘仅写入项目目录 |
| 并发 | 所有落盘与生成在 `_lock` 内串行；同一项目并发调用排队 |
| 只读原则 | 底图 DWG 与编录数据只读，生成过程不修改项目目录内源文件 |
| 响应 | 统一 `{status, project_code, files, results, errors}`；生成接口返回三图各自的调用结果 |

### 7.3 菜单与命令

不变：仍为"一键平面图"（`_SLPlanView`），无需新增命令。

## 8. 异常与边界处理

| 场景 | 处理 |
| --- | --- |
| plan_base.json 不存在 / 解析失败 | 打印 `[CAD ERROR] 未找到底图配置，跳过底图`，继续布孔+图例（兼容现状） |
| base_map.dwg 路径为空 / 文件不存在 | 跳过底图导入，打印提示；拟建建筑仍正常绘制 |
| base_map.dwg 读取失败（版本过低/损坏） | `ImportDwgAsBlock` 返回 kNull → 跳过，打印错误码 |
| 某拟建建筑 outline 顶点 < 3 | 跳过该建筑，打印名称与原因 |
| 轮廓坐标含非数字 | 跳过该点所在建筑，打印告警 |
| 轮廓自相交 / 严重畸形 | 正常绘制（平移影子不依赖轮廓凸性），打印提示建议人工检查 |
| shadow.enabled=false | 只画拟建粗轮廓，不画影子 |
| 底图与钻孔坐标系不一致 | 默认约定同坐标系；错位时配置 `registration` 两点配准自动对齐，配准缺失/失败时打印提示并通过 insert/scale/rotation 校准 |
| registration 点数不匹配 / 两点过近 / 计算非法 | 打印告警，回退手动 insert/scale/rotation，导入不中断 |
| proposed_layer 未配置 | 跳过底图提取，走 JSON `proposed_buildings` 兜底（也未配置则跳过拟建） |
| 底图 DWG 无法打开 / 图层内无闭合拟建轮廓 | 告警提取 0 栋，回退 JSON 兜底；均无 → 跳过拟建，不影响底图与布孔 |
| 拟建图层含非闭合多段线/直线/块等实体 | 首版跳过并计数告警，仅处理闭合轻量多段线（后续扩展） |
| 重复执行"一键平面图" | 先 `EraseBaseMapLayers()` + `EraseBlock("委托方底图")` → 重建 |

## 9. 测试与验收

| # | 验收项 | 判定标准 |
| --- | --- | --- |
| 1 | 底图导入 | 配置 base_map.dwg 后生成，底图以块参照出现在"底图-现状"图层，位置/比例/旋转符合配置（显式参数或配准结果） |
| 2 | 底图容错 | 未配置或文件缺失时，仅布孔+图例，无崩溃无报错 |
| 3 | 拟建建筑 | 配置 `proposed_layer` 后，底图拟建图层内的闭合轮廓被提取为粗线多边形（0.75mm，"底图-拟建建筑物"层），位置/形状与底图一致 |
| 4 | 阴影 | 拟建建筑右下方存在浅灰 SOLID 影子（平移 1.5,-1.5），位于"底图-拟建阴影"层 |
| 5 | 层次 | 打印预览：底图最底、阴影次之、拟建轮廓居中、钻孔/图例最顶 |
| 6 | 重建 | 同一数据重复生成两次，结果图形完全一致（无残留旧实体） |
| 7 | 双版本 | AutoCAD 2005 与 2007 均编译通过、运行正常（含 SOLID 填充与配准计算） |
| 8 | 网关 | 项目制链路：`POST /api/project`（建项目+底图）→ `PUT /api/project/borehole?project_code=` → `PUT /api/project/plan_base?project_code=` → `POST /api/draw/plan?project_code=`，落盘文件与图形正确 |
| 9 | 两点配准 | 配置 source/target 两对点后，底图自动平移到正确位置，比例/旋转与配准计算一致；点对非法时回退手动参数不中断 |
| 10 | 提取回退 | proposed_layer 无闭合轮廓 / DWG 无法打开 → 告警并回退 JSON proposed_buildings；均无则跳过拟建，流程正常 |
| 11 | 真实底图联调 | 用委托方提供的村子总平面 DWG 实测：钻孔点位落在底图正确位置，拟建轮廓粗线+阴影与底图要素一致 |

## 10. 后续扩展（可选，不在首版范围）

- **XREF 外部参照模式**：底图以外部参照引用（不拷入图形数据库，底图大/委托方会更新时更优），并支持重载；
- **多点配准（最小二乘）**：两点配准（首版能力）为相似变换精确解；若需 3 点以上冗余观测求最优解、或处理底图不等比/非正交变形（仿射配准），列为扩展；
- **交互式配准**：在 AutoCAD 内拾取底图两点与钻孔两点（对应理正"底图初始化"交互界面），替代 JSON 配置点对；
- **拟建轮廓实体扩展**：首版提取闭合轻量多段线；旧式 2D 多段线、直线/圆弧组合轮廓、块内拟建实体、图层内按颜色/线宽筛选等提取规则列为扩展；
- **底图图层映射**：按图层名将底图内已有建筑/道路自动映射到规范图层并置灰（对应理正"图层匹配"）；
- 拟建建筑名称、层数标注（`AddDbText` 写"×××楼（×层）"）；
- 指北针、比例尺、图框；
- 分幅出图（对应理正分幅功能）；
- 剖面线投影与钻孔桩号自动计算（对应理正"投影剖线"）。
