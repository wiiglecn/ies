- **底图 = 必需**。钻孔坐标是"某坐标系里的数字"，没有同坐标系底图就失去参照系。需规 L104 明确成图顺序：底图 → 拟建影子 → 拟建轮廓 → 钻孔 → 图例。用户说的"地图"就是底图，绕不开。

## 问答：拟建建筑是否惯例放在 AutoCAD 的 0 层？

用户问：基建/总平面底图里，拟建是否一般放 0 层。主理人只读核验（改了记忆文件，未改项目文档/代码）。

### 已核验事实
- 本项目**真实样例是图层名 `0-规划建筑`**（非 AutoCAD 的 `0` 层）：需求文档 L149/L310/L320，阳光幸福里项目 `05阳光幸福里总平面规划图104(1).dwg`，客户截图确认。
- 需求文档 L88 只说"总平面图惯例画在专门图层（如'拟建建筑'层）"，并未规定 0 层。

### 结论
- **真·0 层：不会、也不该**。0 层是 AutoCAD 系统层，国标 CAD 制图规则留给"块内几何"，正式图面内容不放；且对本插件是最坏情况——0 层是公共层会混入底图杂项，按"层名=0"提取会误抓/失败。

- 最稳：直接向委托方索取"拟建层名"并确认该层未混入其他内容（需规 L176 已如此要求）。

## 问答：理正"模式A（底图作背景+布孔，不提取不重画）"说法是否成立？

用户转述外部资料（道客巴巴）：理正是"底图初始化 → 生成平面图 → 布孔"，拟建建筑就是底图自带内容，理正不提取不重画。问主理人怎么看。主理人只读核验（读了 CreateBaseView.cpp / CreatePlanView.cpp / 需求规格说明书.md），未改任何文档代码。

### 核验到的事实
- **代码已是"模式A"**：`CreateBaseView.cpp:120` 整张底图 DWG 作**一个块**导入（`pCurDb->insert(blkDefId, szBlockName, pExtDb, true)`），不炸开；`CreatePlanView.cpp:111/119` 布孔直接拿 `X坐标(m)`/`Y坐标(m)` 当插入点（真实坐标）。→ "底图当背景、不重画" 这半句已在代码落地，成立。
- **"不提取"与需规直接冲突**：需规 R9"从底图指定图层**自动提取**拟建建筑轮廓，粗线绘制"、R10"自动生成浅灰影子"、L104 成图顺序"底图→拟建影子→拟建轮廓→钻孔→图例"。→ "不提取"不成立。
- 图例里有"拟建建筑物及层数/已有建筑物及层数"图标（PMXnjz/PMYyjz 块，`CreatePlanView.cpp:480/518`），进一步说明规范要求区分已建/待建。

### 主理人结论
- **"不重画" ≠ "不读取"**：底图整体块引用（不读图层名）与"抠出拟建这一层画粗线+影子"是**叠加**关系，不是二选一。
- **逻辑反问戳破"不提取"**：理正若不画阴影→你 R10 要画→必须读拟建层；若画阴影→更说明它要读轮廓。两情况"不提取"都站不住。判断：那份资料只讲**主干交互流程**，没讲**成图规范**，被误读成"理正啥都不做"。
- **模式A有硬前提**：底图须在真实坐标系（1:1）。需规 R7 已承认会不一致（两点配准）；光栅扫描底图更只能对齐——纯模式A覆盖不了。
- **推荐架构**：底图整体=模式A（不读图层名，布孔永远稳）；拟建单点=模式B（读 1 个图层名）。**"图层结构不一"的战场从整张图缩小到一个图层**，且按 R24 单项失败不中断、拟建层名做成可选配置。
- **给用户拍板的问题**：影子（阴影）是否必须交付项？是→走"整体A+拟建B"；否→可退化纯模式A（架构最简）。建议保留 R9/R10 但影子降级为可选开关（R10 本就写"可整体开关"）。
